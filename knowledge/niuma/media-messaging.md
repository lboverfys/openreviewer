# NiuMa 媒体、会话与实时通信

适用仓库：lboverfys/NiuMa

## 媒体上传、审核和引用（MediaAsset、MediaReference）

适用于 content 媒体、头像、认证材料、作品、聊天附件和录音。上传任务、对象上传完成、服务端校验、审核通过与业务引用是不同事实。只能引用本人有权使用、用途正确且满足该用途审核策略的资产；审核材料不因上传成功就进入公开资料。

业务对象替换或删除只释放本业务引用，不直接删除仍被其他对象使用的文件。对象清理由持久任务在数据库事务外执行，并能处理失败和重试。不能仅凭存在对象存储地址就绕过权限或当作已可公开内容。

## 私有媒体的读取授权（MediaAsset、Download）

适用于预览、下载、短期签名地址、分享和客服取证。先按当前业务对象与用途校验可见范围，再授予有限期访问。认证材料、私聊附件和订单录音不能经公开列表、搜索或日志泄露。缓存结果也必须保持身份、对象和权限边界。

公开且已经审核发布的作品可以按公开契约读取；不要求所有媒体都强制登录。授权到期后的重新签发必须重新核对权限，不能用旧可见状态无限续期。

## 需求房、订单房与沟通资源（Conversation、WebSocket）

适用于 communication 会话、成员管理、客服介入和房间关闭。demand 与 order 决定业务生命周期，communication 保存对应会话、成员、消息及语音关联，不能反向修改订单、需求或资金状态。候选进入需求房不等于成为正式订单成员。

HTTP 读取、历史消息、发送、WebSocket 订阅和文件访问都遵守当前成员权限。账号停用、设备下线或业务撤权后，旧连接不能长期继续读取受保护内容。仅在首次连接鉴权不足以证明撤权后的访问安全；若现有机制持续校验或及时断开，则不重复要求另一套机制。

## 消息身份、顺序与通知（Message、Notification）

适用于发送重试、实时推送、历史分页和重连补发。使用服务端消息 ID、clientMessageId 或已有事件身份合并，避免把重试显示两次；两条文字相同但身份不同的消息仍是两次独立发送，不能按内容去重。历史游标与稳定顺序不能因新消息插入而覆盖或跳过应展示内容。

notification 管理接收人、投递和已读事实，不以“投递成功”代替订单或审核成功。重要业务通知需要复用现有可靠任务与重试，旧事件不能覆盖新状态；纯展示刷新应按实际丢失影响判断。

## TRTC 入房与录音是两类授权（VoiceIntervention）

适用于语音、视频、试音、客服入房和云录制。NiuMa 音视频能力使用腾讯 TRTC，业务入房凭据绑定当前用户、房间、角色和有效期。用户同意客服入房不等于同意录音；两类决定分别校验、记录和推进版本，拒绝或撤销要影响对应能力。

外部 SDK、录制或审核适配器未配置时明确返回不可用，不伪造令牌、录音地址或审核通过。能签发业务凭据不等于真实通话已经建立。新增合法云录制或审核接入应依据实际实现检查，不能被旧环境的“暂未配置”描述永久阻断。
