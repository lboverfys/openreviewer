# NiuMa 账号、终端权限与资源归属

适用仓库：lboverfys/NiuMa

## 会话、终端、权限和本人资源（Authentication、Authorization）

适用于四端 HTTP 接口、WebSocket、下载和批量查询。身份使用 Sa-Token 有状态会话，不能当作 JWT 自行解析。登录有效、portal 合法、操作权限和资源归属分别成立；本人 userId、companionId 从服务端当前身份解析。请求携带的对象 ID 只用于定位，不能证明访问权。

用户只能访问自己有权查看的订单、工单和媒体；打手只能操作本人档案及参与的业务；客服按分配与可见范围处理资源。需求房候选资格不等于正式订单成员，允许进入一个终端也不等于拥有该终端所有管理权限。

## 单账号单身份与管理员保护（AdminAccount）

适用于注册、角色维护、账号恢复和权限变更。NiuMa 采用单一角色模型，数据库对 identity_user_role.user_id 有唯一约束，不允许同一账号关联多个角色；角色内可以拥有多项权限。不能把权限集合误解为多角色，也不能要求恢复旧文档的多选角色。

管理员敏感写入需要管理端权限、明确原因、二次验证和目标版本校验。停用、删除或剥夺管理员资格不能消灭最后一个可用管理员；并发操作要在同一保护范围内重新检查操作人和目标的有效性。账号恢复默认仍停用，不自动恢复登录资格。

## 二次验证、密码与会话失效（IdentitySecurity）

适用于修改密码、邮箱、角色、状态和设备下线。验证码或二次凭据按账号、终端、用途和有效期校验并原子消费，不能被跨操作重放。密码按实际哈希算法的字节约束校验，不能把 Unicode 字符数与 UTF-8 字节数当作同一上限。

高成本哈希计算和会话存储清理离开数据库事务；写入按账号版本避免覆盖并发变更。敏感身份变化后的旧设备与实时连接按现有失效机制处理。只改变展示昵称不能被机械要求按权限变化处理；报告需指出真实残留权限或会话可用路径。

## 账号资料与公开打手资料分开（AccountProfile）

适用于昵称、头像、认证材料与服务档案。账号资料的编辑权限不等于游戏资格、报价或公开作品的发布权限。头像只能引用本人、用途为 ACCOUNT_AVATAR 且已通过实际文件校验的资产；保存时更换的是本业务引用，不能删除其他业务仍使用的对象。

认证材料仅本人和授权审核人员可读；公开作品须满足相应审核和发布条件。账号软删除保留历史订单、积分、邮箱归属和审计，不通过级联删除清空交易事实。审查应核对目标用途的实际审核策略，不能假设所有图片都走相同审核流程。
