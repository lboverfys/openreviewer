## 会话、终端和资源归属

- NiuMa 使用 Sa-Token 有状态会话，不能把 Token 当作 JWT 自行解析。
- 登录有效、portal 正确、细粒度权限和资源归属必须分别成立。已登录不代表可以访问任意订单、会话、媒体或打手档案。
- 当前用户及本人打手 ID 来自服务端登录态，不信任前端提交的 userId/companionId 作为访问依据。
- 用户端只能读取本人订单及其可访问对象；订单房仅允许订单成员和获授权客服。试音房候选身份不等于正式订单房成员。
- 语音介入的入房授权和录音授权是两类决定，必须分别记录、版本校验；不能将允许入房自动解释为允许录音。

## 管理员写入与账号保护

- 创建、修改、重置密码、删除和恢复账号，需要管理员权限、操作原因及一次性二次验证凭据。
- 删除账号为软删除，历史订单、积分、邮箱归属和审计保留；恢复后保持停用，核对后再启用。
- 禁止停用、删除或剥夺最后一个可用管理员。并发管理员操作需要共同的锁和目标版本校验，不能只在前端禁用按钮。
- 邮箱、角色、状态或密码变化后撤销旧登录设备；操作人修改自身资料时也要正确处理重新登录。
- 旧账号管理文档曾允许多角色；2026-09-07 之后的资料说明与约束改为单账号单身份。按目标提交的约束核对，不能要求恢复旧多选角色。

## 接口与前端显示

- 业务 ID 以字符串传到浏览器，避免 BIGINT 被 JavaScript Number 截断。
- 业务写入沿用 Idempotency-Key 和 expectedVersion。同一个逻辑重试复用幂等键，同键不同参数必须冲突，不能重复扣费或覆盖他人修改。
- 成功、失败、分页使用项目现有 Result/PageResult。业务码以最新 error-code-conventions 的五位字符串为准；飞书旧示例中的 code=0 不是最新格式要求。
- 401、403、409 分别按会话失效、无权访问、版本冲突处理。不能只用前端隐藏按钮替代后端鉴权。
- 只有确认接口确实可能返回 null/缺省字段后，才报告空值异常；核对 DTO 和服务端归一化逻辑，避免凭空假设响应违约。
