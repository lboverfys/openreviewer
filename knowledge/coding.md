# 接口契约、前端状态与可维护性

## 输入输出的类型和兼容性

适用于 API、DTO、序列化、前端请求与响应处理的修改。对照实际调用方检查字段名称、类型、必填性、空值、枚举、计量单位及分页含义。长整数标识跨到 JavaScript 时不能失去精度；金额不能混用元、分、积分；时间点、时长和业务日期不能相互替代。

字段删除、改名、含义变化或默认值变化造成现有调用失败时，才是兼容性缺陷。未知字段是忽略还是拒绝，应服从现有接口策略，不对所有协议强加同一种处理。兼容字段仍被实际客户端使用时，不能仅因为看起来冗余就要求删除。

## 前端异步请求与页面归属

适用于列表筛选、分页、路由切换、弹窗编辑和异步详情加载。旧请求的结果不能覆盖新筛选、新页码或另一个资源；用户快速切换时，提交动作必须绑定当前资源和读取到的版本。监听器、计时器、订阅及连接应在失效时释放，避免重复处理和持续占用资源。

报告时说明用户操作顺序、响应返回顺序和错误展示或错误写入。若现有请求取消、请求序号、缓存键或组件生命周期已保证归属，则不重复要求额外机制。

## 保存失败和冲突不能伪装成功

适用于表单、状态按钮、批量操作、上传与删除。成功反馈必须对应服务端确认的结果；乐观更新失败要能恢复或重新取得真实状态。权限失败、版本冲突、校验失败和请求结果未知需要可区分，不能统一吞掉异常或展示成功。

同一动作提交中应避免无意重复操作，重试身份由业务契约决定。可安全重放的幂等请求不必因为重复发送就被判错；请求超时也不能直接当作服务端没有执行。删除末页最后一项后，分页需要能返回仍有数据的有效页。

## 业务状态必须表达真实事实

适用于进度、审核、任务结果和权限相关页面。等待、执行中、失败、部分完成、跳过与完成不能混为一谈；空数据、加载中、无权限和没有结果应有不同含义。界面显示可操作不构成后端授权依据。

只报告会误导用户作出操作、隐藏失败或阻断主流程的状态错误；不把个人视觉偏好当作功能缺陷。遇到空值先检查响应契约与归一化处理，不要求为永远不可能出现的状态堆叠兜底。

## 模块边界与测试价值

适用于跨模块依赖、业务逻辑复用和测试调整。复用已有权限、分页、错误处理、事务与数据访问入口，避免新建另一套互不一致的实现。关键规则应由能够覆盖所有真实调用路径的位置执行。

不要仅因函数较长或出现重复文本就要求重构。需要指出重复实现如何发生行为分歧、依赖方向如何破坏约束，或修改如何使已存在的关键验证失效。关键测试应验证业务结果和失败边界，不仅复制实现步骤。
