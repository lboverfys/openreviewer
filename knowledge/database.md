# 数据访问、事务与数据库演进

## 批量查询与有界数据

适用于数据库查询、ORM 关联加载、列表聚合与导出。批量对象先收集条件，用 IN、JOIN、预加载或已有批量接口取回，再在内存匹配，避免每个对象额外查询的 N+1。跨表数据优先由有界 JOIN 完成；多条固定次数的批量查询也可以成立，不应误认为逐条查询。

查询只取需要的列。列表有分页或硬上限，导出按批次或流式处理；查询一次后把大表全部装进内存仍有风险。报告需指出数据来源、预计增长量和查询次数，而不是把只遍历几个内存对象的循环当作数据库问题。

## 索引、排序与分页语义

适用于过滤、联查、排序、游标和统计。结合 WHERE、JOIN、ORDER BY 与已有索引检查访问路径；稳定分页需要确定的排序，必要时用唯一键打破相同排序值。避免在索引列上做无配套索引的转换或运算，避免深分页与不必要的大范围计数。

LIMIT 只约束返回数量，不保证少扫描数据。性能缺陷需结合实际规模、执行计划或可证明的查询形态；小型配置表的顺序扫描不等于故障。有合适的表达式索引、部分索引或已限定唯一键时，不能只看 SQL 外形就否定索引使用。

## 并发写入与约束

适用于余额扣减、资源占用、审核、唯一业务号和状态转换。先读后写必须由数据库条件更新、乐观锁、唯一或排他约束、行锁等保证结果；多实例进程内锁不能独自保护共享数据库。更新条件应包含主键以及业务所需的预期状态或版本，并检查受影响行数。

幂等记录与业务结果应能一起提交或一起回滚。多资源操作按一致顺序锁定，等待锁后重新核对会变化的条件。已由唯一约束或同一事务锁保护的路径，不要求再增加一套分布式锁。

## 事务范围与外部副作用

适用于跨服务编排、上传、通知、支付渠道和后台任务。应在同一数据库事务内保持一起生效的事实一致；跨域调用同库 Service 不等于远程调用。文件 IO、HTTP/RPC、耗时哈希和不受数据库回滚控制的外部写入不应占着数据库锁执行。

需要外部副作用时，复用已有提交后机制、任务或 Outbox，并明确失败恢复与幂等。只有提交后回调但没有失败恢复能力时，不能声称已经实现可靠投递；也不能在没有跨边界一致性需求时强制引入消息队列。

## 迁移必须覆盖旧数据和发布顺序

适用于 schema、索引、约束、基础数据和数据修复。已经在任一共享环境执行的迁移应保持不变，后续使用前向修复。新增非空、唯一或外键约束前检查存量数据，回填有明确范围，大表变更评估锁和耗时；空库通过不等于旧库升级安全。

数据库变更需与实际部署方式兼容。若存在新旧实例共存或回退窗口，应保留必要的旧字段与读取能力；受控停机且明确完成协调的改动不应被机械要求永久双写。正式环境不能加载演示账号和个人测试数据。
