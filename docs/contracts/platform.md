# 团队运营契约

## 外发检查、质量提示与精确输入复用

仓库策略新增 `egress` 与 `incremental_review`。外发策略包含禁止文件通配符、供应商完整域名
白名单及高置信凭据检测开关。默认禁止 `.env`、私钥文件及可识别凭据；白名单为空时使用已配置
连接。命中时整次拒绝，不修改源码、行号或证据哈希，不预占费用、不发送 HTTP。不会宣称能够
识别所有业务敏感信息。拒绝审计只保存原因与可选输入哈希。

固定流程每个 Agent 开始执行时读取当前外发策略；检索、手工搜索、评测和索引补全在操作开始
时各读取一次。进行中的 HTTP 不会被策略修改追溯撤销。批量循环内不重复读取策略；向量与精排
正文同样检查。凭据连接测试没有仓库身份，只使用连接自身的安全约束。

方案启用前提供 `/platform/profiles/{id}/quality`。选择验收评测集后，核对基线绑定当前启用
方案、候选绑定目标方案；要求至少 20 组完整双人复核、三类样本、完整独立调用版本及费用。
该数量是初始流程要求，不是统计准确率保证。缺失数据显示未验证，质量下降单列；费用增加
提示人工判断。未验证或退步方案必须填写启用理由。启用事务锁定仓库及评测集，重新计算证据
指纹，旧页面返回 409。审计保存报告版本、状态和人工理由。仓库策略接口不能绕过此入口切换方案。

跨提交复用默认关闭，要求绑定不可变方案。MVP 按 Agent 的完整输入复用，键包含代码正文、
文件 Blob、位置、关联证据、知识版本、方案、连接、模型参数与程序镜像；仅移除提交身份。
本次全部非文档变更是保守失效范围，任一变化均放弃复用。缓存最长七天且跟随来源任务清理，
单项结果最多 256 KiB。此实现不宣称已经能证明任意跨文件依赖完整或只重查最小受影响方法。

命中结果重新绑定当前单元与证据引用，继续当前提交的物化校验，保存独立批次及来源运行。
汇总仍按现有流程重新执行；本次模型 Token、HTTP 次数和费用为零，原消耗保留在来源运行。
已有本任务批次时优先断点恢复，不用跨任务缓存覆盖。对照评测必须关闭复用，含复用记录的样本
会被质量提示标为不满足独立调用条件。

入口为“团队管理”和“协作与运营”。完整请求与响应字段见 [OpenAPI](../openapi.json)。

## 成员与仓库

配置管理员继续由部署配置维护。普通成员存入数据库，支持角色、安装/仓库范围与启停。
修改权限、密码或状态会递增成员版本并撤销旧会话；SSE 也会检查会话状态。非管理员默认
拒绝未声明的范围。首版是一个团队的多个仓库，管理设置权限仍是团队级权限。

仓库策略维护接收开关、目标分支、知识来源、审批负责人、单次审查请求数、审批时限、月度
预算、预算提醒比例、并发上限和审查方案。保存要求 `expected_revision`，过期返回 409。
策略不会扩大 GitHub App 的实际授权。

| 设置 | 生效边界 |
| --- | --- |
| 接收、目标分支、知识范围、审批负责人、请求数上限、方案 | 创建新任务时保存策略快照 |
| 月度预算与提醒比例 | 每次模型请求预占时读取当前策略 |
| 仓库并发上限 | 每次任务领取时读取当前策略 |
| 审批截止时间 | 完整审查进入审批时，依据该任务的审批时限计算 |

## 月度费用

月度账本按 installation、规范化仓库名、UTC 自然月区分。内部使用整数微美元，展示为美元。
费用来自配置价目，不等同于供应商账单。未设置预算时也记录新请求；历史运行不补造费用。

当前计费边界是审查任务内的模型请求，包括审查中的向量和精排。独立索引构建、手工检索与
连接测试不计入该任务账本；页面明确使用“审查流程”口径。

1. HTTP 前验证租约和当前预算，预占单次请求估算上界并保存独立请求记录。
2. 并发请求通过同一月度行的条件 UPDATE 累加；余量不足时不发送请求。
3. 成功或失败后以请求状态比较更新结算。同一请求重复结算只生效一次，重试则是新请求。
4. 无价格、无用量、网络不确定和仍在途请求分别保留。用量不确定时保留必要预占，不按零处理。
5. 月末后的迟到结算仍归入原请求月份。任务清理不级联删除月度汇总与请求账本。

开启预算且价格未知时拒绝新请求。预算不足使工作流暂停，已完成批次保留；调整预算后可从
审查详情恢复任务，或等待新月份后人工恢复。增加预算不会静默触发真实模型调用。
金额上限限制的是配置价格下的估算准入，供应商额外计费与用量缺失仍需要对账。

各 Agent 可单独配置输入、输出和缓存价格。共享连接只在模型名称相同时继承公共价格，
不同模型没有节点报价时仍显示未知。仅修改价格且实际连接指纹不变时保留连接验证及启用
状态，不会发起模型测试；固定方案仍保存自己的报价快照，更新后需要保存新方案。

用量页面提供月度汇总、按模型/用途分组和请求分页。预算提醒依据已估算金额加保留预占。
同一月份、预算和提醒比例使用稳定事件键去重，预占释放后再次越过提醒线不会重复生成通知事件。
分组最多展示 100 个模型/用途组合，未知数单独列出。

## 供应商故障隔离

连接身份由供应商地址与密钥的哈希确定，数据库不保存明文密钥。每个连接最多三个在途请求。
连续五次限流、服务错误或无响应后熔断 60 秒；之后只允许一个请求探测，成功后恢复。
鉴权、参数等确定的客户端错误不冒充暂时性服务故障。

并发准入与请求状态在短事务中保存，HTTP 不持有锁。请求租约到期后不再占用通道，费用预占
仍保留以便核对。拒绝准入没有发送 HTTP，沿用批次等待与退避机制。
运营诊断向全量范围管理员展示连接哈希、在途请求、失败次数和熔断时间。

## 人工待办与经验

一个 Finding 对应一个独立工作项，保存来源、负责人、截止时间、处理说明和同仓库修复 PR
编号。支持待处理、处理中、人工确认修复、暂不修复；完成类状态要求填写说明。
更新检查版本，不允许过期页面覆盖最新结论。负责人必须启用且有对应仓库的处理权限。

待审批列表按真实 `awaiting_approval` 查询，支持我的待办与超期筛选。未指定负责人时由有
审批权限的成员处理；历史任务没有进入审批时间时，不伪造截止时间。
历史策略中已经指定的审批负责人继续生效，不会因为新增投影字段为空而变成公共待办。

已保存的人工处理结论可以整理为知识草稿。提交要求工作项版本与知识库版本，记录来源及
人工总结。草稿默认未启用，具有明确仓库范围；管理员审核启用后才参与该仓库的规则检索。
同一来源重复创建会明确冲突，后续修改复用知识库的版本、归档和恢复机制。

工作项状态、Finding 有效性、算法跨提交追踪与评测标签是不同事实；它们不会自动互相覆盖。

## 不可变审查方案

保存方案时捕获四个就绪 Agent 的模型参数、Prompt 模板、知识内容及版本、检索参数和凭据。
捕获前后的 AI、知识、检索与仓库版本必须一致；否则放弃本次捕获并返回冲突。
快照最多 2 MiB，列表只读轻量摘要；凭据放入独立 AES-GCM 信封，管理 API 不返回密文或明文。

启用或恢复某个方案要求当前仓库版本号。方案本身不可编辑，修改配置后保存新的方案。
任务保存方案 ID，Worker 每次恢复都读取同一个不可变版本。未绑定方案的仓库沿用现有配置
机制，页面明确显示该状态。

方案协议与当前程序不兼容时拒绝使用，不静默解释为新版本。源码规则仍绑定 PR SHA；索引
仍绑定同一提交。程序镜像版本与模型批次记录用于追溯，方案不声称冻结所有未来代码行为。
检索外部调用暂停开关始终具有优先级，旧方案不能重新开启被暂停的外部调用。

## 运行诊断与数据访问

Worker 节点在运行诊断中独立管理，提供在线、离线与全部记录筛选及每页十条游标分页。
在线判定为最近 15 秒有心跳且未上报 stopping；“最后上报状态”与当前在线状态分别展示。
节点是团队共享运行信息，关联任务 ID 和跳转仍按安装/仓库范围隐藏。管理入口需要配置管理权限。
列表按启动时间和 Worker ID 排序，普通心跳不会移动分页位置；同一稳定 ID 重启后代表新一轮进程，
会更新启动时间。历史沿用默认七天保留期，页面显示实际配置的保留天数，后台按现有批次清理。

控制台只返回最多三个在线节点的预览，在线与忙碌总数由数据库在 LIMIT 之前计算；无在线节点时
仅保留一条最近心跳作为离线诊断信息。SSE 不再携带大段离线历史，预览之外的在线数量或忙碌数量
变化仍会更新变化令牌。清理删除时再次核对 last_seen_at，避免等待行锁期间刚恢复的心跳被删除。

按仓库展示当前排队、运行、暂停，以及所选时间范围的审查产出、失败、平均/P95 首次排队
耗时、平均累计模型耗时和错误原因。排队积压包含更早的待处理任务；P95 仅在支持的
PostgreSQL 聚合路径计算，缺数据返回 null。

| 数据 | 规模与访问方式 |
| --- | --- |
| 月度汇总、仓库与方案摘要 | 仓库数百以内；稳定游标与 LIMIT，单页一条查询 |
| 请求账本、工作项、任务与审计 | 万至十万行；范围与排序索引，正文按需读取 |
| 月度模型分组 | 指定 month_id 的数据库聚合，固定两条查询含授权确认 |
| 请求预占/结算 | 每个 HTTP 请求固定数量 SQL，锁顺序为通道、请求、月度行 |
| 运行诊断 | 数据库聚合，最多 100 仓库、50 错误类别、100 通道，查询次数 O(1) |
| 方案捕获与成员校验 | 固定版本读取、批量来源数据，无按文档或模型逐项数据库查询 |

新记录使用 `repository_usage_months`、`model_usage_requests`、`finding_work_items`、
`review_profiles`、`repository_schedules` 和 `provider_circuits`。身份、知识、任务及 Outbox
继续复用原表。索引、并发竞争和十万行分页由 CI 隔离 PostgreSQL 验证。
