# 审查流程契约

## 静态检查佐证

任务详情可导入 Semgrep 的单运行 SARIF 2.1.0。每份文件最多 1 MB、500 条结果；可同时提交
同扫描器版本的基线报告。导入者需要问题裁决权限，目标 head/base SHA 必须匹配该任务固定版本。
解析在事务外执行，存储时重新检查权限和提交；报告不可覆盖，同一报告重复导入返回原记录。

路径必须属于仓库，拒绝绝对路径、目录穿越与远程 URI。只有同版本基线和 Semgrep 的稳定
`matchBasedId/v1` 都存在时，才区分基线已有与未出现的问题；缺少身份或被抑制的线索显示待判断。
空结果与扫描失败分别处理。报告来自登录成员导入，SHA 关联不等同于已验证 CI 工件签名。
两份报告仍需由导入者确认扫描范围和规则配置一致；“基线未出现”不直接证明该缺陷由本次 PR 引入。

静态线索与 AI Finding 分别保存，分页展示同文件同行范围的 AI 问题数。位置重合只是核对入口，
不能自动视为同一个缺陷，更不能自动裁决、批准或发布。平台不运行被审查仓库的脚本。

接口字段与枚举见 [OpenAPI](../openapi.json)。本页只维护跨阶段必须一致的行为。

## 接收与版本

- 接受 GitHub `pull_request` 的 opened、synchronize、reopened、ready_for_review 事件。
  HMAC-SHA256 验签、安装及仓库白名单、256 KiB 正文上限在接收边界完成。
- Webhook 以 delivery ID 去重；手工创建要求 `Idempotency-Key`。相同键与内容返回原任务，
  同键异内容返回 409。
- 版本身份为 `{repository_id}:{pull_request_number}:{head_sha}`。仓库数字 ID 是稳定身份；
  仓库名称用于授权和展示，规范化的 `repository_key` 用于索引查询。
- ReviewRun、ReviewTask、接收记录及 Outbox 在一个事务保存。暂停仓库或目标分支不匹配
  会给出明确原因，不创建“通过”的结果。

## 调度与执行权

每个 Worker 进程同时处理一个任务，支持多个副本。任务达到 `available_at` 且处于可领取
状态时，使用 `FOR UPDATE SKIP LOCKED` 领取。领取事务同时更新运行、任务、尝试代次和
租约，写入 Outbox；外部操作在事务提交后进行。

仓库并发上限在领取时检查。一个非阻塞事务级 advisory lock 保护“检查活跃数量并领取”的
临界区，避免多个 Worker 同时越过上限；同优先级按仓库上次领取时间轮转，再按可用时间与
创建时间选择任务。锁仅覆盖数据库领取，不覆盖整次审查。

写回与续租核对任务、Worker、失败尝试代次、模型尝试代次、CI 轮询代次和到期时间。
过期或被暂停的任务不允许旧租约继续写入。过期恢复使用有界批次与任务/运行 JOIN。

默认最多三次错误尝试，退避从 5 秒开始，最多 300 秒。等待 CI、等待索引、批次占用和
供应商通道等待分别保留自身语义，不能当作已经发送了模型请求。正常 CI 轮询不消耗错误
尝试次数。稳定错误码、安全说明与脱敏详情贯穿日志、数据库和 API。

## 代码、CI 和规划

GitHub App 使用短期 installation token。首次读取固定 SHA 的 PR、变更文件、完整 diff 和
CI；后续 CI 轮询复用文件快照。分页和大小边界必须能证明读取完整，不能把截断当作完整。
新 SHA 淘汰旧审查；关闭/Draft PR、等待超时分别进入对应终态。

CI 为 success、failure 或完整读取后确认 not_configured 时进入规划；unknown 继续等待。
`AGENTS.md` 通过批量读取加载目录作用域，生成确定性的 Review Unit。所有可审查文件均进入
计划；模型上下文不足时分批，单个大文件按行切片，不静默漏掉剩余文件。

## 模型与证据

安全、规范、逻辑三路按职责处理适用单元，汇总处理结构化候选。支持 OpenAI Responses、
Chat Completions 和 Anthropic Messages；统一适配严格结构化输出、Token、耗时和估算费用。
允许的协议降级有明确条件，鉴权失败、限流或任意 4xx 不能被误判为可选参数不兼容。

每批保存输入身份、配置、状态、尝试次数、租约和检查点。恢复时复用已完成批次；截断后的
拆分也有持久化检查点。最终结果只有在租约、计划指纹和 SHA 均有效时才原子入库。

Finding 保存严重度、类别、标题、证据、影响、建议、可选回归建议、位置与引用。平台生成
稳定指纹和 SHA；模型不能自报可信的验证状态。位置匹配、源码证据匹配和人工有效性裁决
各自记录。模型置信度不等同于实际正确率。

PR diff 中的位置可以用于行内评论；检索到的未改动代码只作为跨文件判断证据。未知引用、
不一致的内容哈希和计划外单元不能进入可信结果。

## 人工门与发布

```text
AI 结果保存 → awaiting_approval → awaiting_publish → publishing → completed
```

批准不触发外部写入。只有具有发布权限的成员显式点击发布，API 才调用 GitHub。
发布前重新读取 PR，要求仍然 open、非 Draft 且 SHA 一致。

可发布载体为一个 Check Run、最多 50 条行内评论和一条汇总评论。有效问题才进入 Check 与
汇总；行内还需通过位置、源码证据、风险域历史评测准入和置信度要求。位置被 GitHub 拒绝
时可降级到 Check/汇总，并明确说明。

Check external ID、汇总标记和行内问题标记由运行、版本、指纹生成。网络超时后先读取远端
对象再更新或补发，防止重复评论。远端不提供跨请求事务，SHA 校验与写入之间仍有竞态窗口。

数据库先记录 publishing 并提交，再访问 GitHub，最后用新事务收口。发布失败可重试，长时间
停留在 publishing 的尝试允许恢复。数据库迁移和外部发布都不以“静默回退成成功”处理。

## 权限与安全

`reviews:view` 查看；`findings:adjudicate` 裁决；`reviews:approve` 批准；
`reviews:publish` 发布；管理动作继续使用原角色权限。所有资源查询应用安装与仓库范围，
越权 ID 返回 404。写接口检查同源；会话与敏感配置不存入前端可读存储。

读取 token 只申请只读范围；发布 token 只申请 checks/pull_requests 写权限。
模型、规则和补丁均不能触发任意脚本执行。PR 提供的指令作为不可信上下文处理。
