# 真实 PR 评测工作台

本工作台衡量真实审查流程在人工复核样本上的效果，复用现有角色、资源隔离、审查结果和
离线评测的比例/Wilson 区间算法。不会把结构化结果快照冒充供应商原始响应，也不替代
evaluation.md 中的原始模型观测文件契约。

## 使用流程

1. 从“评测工作台”或任务详情的“加入评测”入口，选择已完整完成 AI 审查的运行。
2. 创建评测集并收录基线；每个评测集属于一个仓库和 GitHub App 安装范围。
3. 收录同一 PR、同一提交 SHA 的候选运行。同一个 PR 在集内只能绑定一个提交与一种划分。
4. 设置参考标签：未标注、没有已知缺陷、已知缺陷列表。保存标签不等于完成复核。
5. 两位不同的登录成员分别确认参考标签，并独立保存每条问题的结论后提交本组复核。
6. 对比报告按调参集、验收集分别计算，可导出仅含聚合统计的 JSON。

只有拥有 findings:adjudicate 权限的成员可收录和复核；reviews:view 可查看。
所有列表、详情、原始变更与聚合查询均通过评测集的安装和仓库范围做数据库过滤。
复核人从登录会话取得，请求体不能指定或伪造 reviewer。

## 数据与版本

- evaluation_datasets 保存名称、仓库、归档状态和样本数。
- evaluation_cases 保存 PR、SHA、固定的 tuning/validation 划分、参考缺陷与两人确认。
- evaluation_observations 每个样本最多 baseline/candidate 两条，保存独立结果快照与复核。
- 原 review_run_id 只作为追溯字符串，不设级联外键；原任务清理后仍保留评测快照。
- 快照保存结构化问题、PR 审查变更、规则内容哈希、模型/协议/Prompt、配置版本、
  检索策略/索引/提交、Token、估算费用和时间，并绑定 SHA-256。
- 新模型批次记录程序镜像提交与真实知识引用版本。历史缺失值显示为未记录；
  同一组有多种配置时，报告明确提示，不把它解释成一次严格控制变量的模型实验。
- 变更代码只覆盖原 Review Unit 中的 PR 变更，未改动的关联文件可在 GitHub 同一 SHA 核对。

记录会先脱敏。单运行最多 500 条问题、500 个审查文件、2 MiB；每次收录最多 30 条运行，
全部快照最多 8 MiB。超限明确拒绝，不静默截断证据。
每个评测集最多 200 个 PR，适合先用 20–30 个真实 PR 建立首轮基线，再逐步扩充。
正常变更、已知缺陷和跨文件样本由成员标注，系统不自动生成“人工金标”。

## 复核与一致性

参考标签和每组观察分别最多由两位不同成员复核。每人可修改自己的结论，不能代替另一位成员。
所有写入带 expected_revision；过期版本返回 409，前端保留输入并允许加载当前记录。
空问题列表也要两人显式提交，不能自动视为审查正确。

同一参考缺陷被多个有效问题匹配时，找回数量只计一次。没有匹配的有效问题单独统计，
不会自动加入参考缺陷。问题有效性或参考匹配有分歧时，该组保留 disputed 状态。

更换观察结果会重置该组复核；修改参考标签会重置本 PR 的参考确认和两组复核。
已有复核时必须显式传 reset_reviews=true。归档保留快照与报告，归档后禁止修改，可恢复。
操作人、事件类型、对象与版本通过现有 Outbox 在同一事务记录，不写入密码、密钥和原始正文。

锁顺序为：源运行共享锁 -> 评测集共享/写锁 -> 样本写锁 -> 观察写锁。
复核期间持有评测集共享锁，归档等待在途复核结束；不同 PR 可并行复核。
收录与替换先获取源运行共享锁，保证提取期间原审查不会被重试或清理。
事务内不发起 GitHub、模型、文件或消息请求。

## 报告口径

| 指标 | 纳入范围 |
| --- | --- |
| 性能配对 | 同一 PR/SHA、两个不同运行均已收录 |
| 质量配对 | 性能配对中，基线和候选均完成双人提交，问题结论一致 |
| 参考配对 | 质量配对中，参考标签另经两位成员确认 |
| 费用配对 | 性能配对中，双方费用均已记录 |
| 有效问题比例 | 质量配对内，有效问题 / 已复核问题 |
| 已知缺陷找回率 | 参考配对内，已找回参考缺陷 / 已知参考缺陷 |
| 定位准确率 | 质量配对内，两人均给出一致定位判断的问题 |
| 任务到结果耗时 | 任务创建到 AI 审查完成，包含排队与 CI 等待 |
| 累计模型耗时 | 原审查持久化的模型调用耗时，并行调用也分别计时 |
| 平均估算费用 | 费用配对内的配置价格估算，不是实际供应商账单 |

缺基线、缺候选、未完成复核、分歧、未知费用和版本缺失分别显示。
没有可用分母时比例为 null，不显示为 0% 或 100%。
调参数据不与验收数据混算；报告默认展示验收集。
小样本比例同时给出 95% Wilson 区间，不能从少量样本声称普遍准确率。

## 查询规模与验证

源数据读取涉及 review_runs、review_plans、model_calls、review_findings、review_units、
model_review_batches、review_plan_rules、pull_request_versions、retrieval_traces、code_indexes。
复核数据使用上述三张 evaluation 表，审计复用 outbox_events，身份复用原会话与成员表。

源表按万行至十万行设计；一次收录最多 30 个运行，用六条批量查询，查询次数 O(1)。
依次使用运行主键/资源索引、计划与调用唯一键、问题运行排序索引、单元计划索引、
批次计划索引、规则计划索引和检索运行索引。问题与变更正文分批读取并检查总字节。
新样本与观察通过批量 INSERT 保存，空值显式写入以避免拆成逐行语句。

评测集和样本列表使用稳定游标和 LIMIT；样本列表一次 JOIN 两组观察，不读取快照正文。
详情只读取单个有界快照，问题与代码分别分页返回。统计在数据库内通过一条聚合 SQL 完成，
不随 PR 数量逐条查询，不把全部正文或复核 JSON 搬进内存。报告查询次数 O(1)。

CI 覆盖权限与同源保护、批量查询数量、来源清理后的保留、同提交配对、样本划分隔离、
双人复核/分歧/未知费用、并发版本冲突、分页与前端交互。真实人工标签由成员提供；
CI 的测试数据不会复制到线上充当评测成绩。
