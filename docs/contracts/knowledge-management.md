# Markdown 知识库管理契约 v1

## 1. 目标与事实来源

知识库用于向固定的安全、规范、逻辑和汇总 Agent 提供审查规则及历史经验。生产环境以
PostgreSQL 中的 `knowledge_documents` 和 `knowledge_document_versions` 为唯一事实来源；
仓库内 `knowledge/*.md` 只用于首次初始化的种子数据，不是运行期间的热更新目录。

首次访问知识库且数据库中还没有文档时，服务按稳定路径顺序读取种子 Markdown，并以
`system:seed` 身份导入为启用的第 1 版。数据库已有任意文档后，不会再次把文件系统内容
覆盖到数据库。所有管理接口都要求已认证的管理员会话。

## 2. 数据模型

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `knowledge_library` | 单例全局修订号 | 仅允许 `id = 1`；每次可见变更递增 `revision` |
| `knowledge_documents` | 文档元数据和当前指针 | `source` 唯一；保存启用、归档时间、`current_version` 和审计人 |
| `knowledge_document_versions` | 不可变 Markdown 内容 | `(document_id, version)` 唯一；保存 UTF-8 内容、SHA-256 和字节数 |

文档 ID 和版本记录 ID 为 UUID 字符串。删除不是管理操作；归档通过 `archived_at` 隐藏，
历史版本保留。归档或恢复归档都会强制 `enabled = false`，恢复后需要管理员再次启用。

## 3. 内容边界

- 最多保留 128 份文档；单份内容为 1 到 512 KiB（按规范化后的 UTF-8 字节数计算），启用文档合计最多 5 MiB。
- `source` 必须是 1 到 200 个字符的知识库内相对 `.md` 路径。反斜杠规范化为 `/`，禁止绝对路径、空段、`.` 和 `..`。
- 内容会把换行统一为 LF，去除首尾空白，并在非空内容末尾补一个换行；空 Markdown 被拒绝。
- 文档名不能重复，版本号必须为正整数。服务端再次执行全部边界校验，不能只依赖浏览器检查。
- 浏览器上传只接受不超过 512 KiB 的 `.md` 文件，并用 fatal UTF-8 解码；非法编码直接拒绝，不用替换字符继续保存。

## 4. HTTP 接口

接口前缀为 `/api/v1/knowledge`，请求通过同源 HttpOnly 会话认证。成功响应均为 JSON。

| 方法与路径 | 用途 | 成功响应 |
| --- | --- | --- |
| `GET /search?q=&limit=` | 检索当前启用且未归档内容 | `200`，返回 `query` 和引用数组 |
| `GET /documents?include_archived=&limit=` | 读取文档列表及库统计 | `200`，返回 `revision`、数量、启用字节数和摘要 |
| `GET /documents/{id}` | 读取当前内容和最多 50 条历史版本摘要 | `200` |
| `POST /documents` | 创建第 1 版文档 | `201`，返回新修订号和完整文档 |
| `PUT /documents/{id}` | 更新元数据或内容 | `200`，内容变化时生成新版本 |
| `POST /documents/{id}/archive` | 归档并停用 | `200` |
| `POST /documents/{id}/restore` | 取消归档并保持停用 | `200` |
| `POST /documents/{id}/versions/{version}/restore` | 从历史内容生成新当前版本 | `200` |

创建和修改请求必须携带 `expected_revision`。修改已有文档、归档或恢复还必须携带
`expected_document_version`。变更响应的 `revision` 是提交后的全局修订号，`document` 是
数据库重新读取后的完整当前视图。

常见错误映射如下：

| 状态码 | 含义 |
| --- | --- |
| `401` | 未登录或会话失效 |
| `404` | 文档或历史版本不存在 |
| `409` | 全局修订号或文档版本过期，需重新读取 |
| `422` | 路径、内容、数量或容量不符合边界 |
| `503` | 数据库或知识库暂时不可用 |

## 5. 版本与并发语义

每个写操作在短事务内锁定单例 `knowledge_library` 行，并比较调用方的全局修订号；修改
文档时同时锁定文档及其当前版本。内容 SHA 不变时只更新元数据，不创建重复内容版本；
内容 SHA 改变时将 `current_version` 加一并追加一条不可变记录，旧版本永不覆盖。

恢复历史版本也会追加新版本，而不是把历史行改写。归档、恢复归档和启停会增加全局
`revision`，因此列表缓存和 Worker 快照都能识别变更。遇到 `409` 时客户端必须刷新库和
文档后再提交，不能自动用旧内容覆盖他人的更新。

## 6. 检索与审查快照

Markdown 按标题切块，单块最多保留 20,000 个字符。检索是确定性的词法匹配，不依赖向量
数据库：英文、数字和下划线标识符按词匹配，连续中文同时保留整段和相邻双字词（例如
“鉴权”“分页”），按查询词重叠度和完整短语命中加分，再按分数、来源、标题稳定排序。
`limit` 范围为 1 到 20；管理界面默认请求 8 条。

每次审查在进入 Agent 循环前读取一次当前启用文档的有界快照（最多 128 份、5 MiB），
四路 Agent 都在这份内存快照上检索。审查进行中管理员修改知识库不会改变已开始任务的
上下文；下一次任务读取新修订。引用包含来源、标题、分数、摘录和内容版本前 16 位，
详情页可据此追溯所使用的规则。

## 7. 安全与前端展示

知识文本按不可信输入处理，不能改变 Agent 工具权限、工作流或输出 Schema。管理 API 不
返回密钥或会话信息。前端预览使用 Markdown 渲染器并跳过原始 HTML；编辑器、上传和服务端
三层都执行大小与编码边界，不能通过预览绕过服务端校验。

文档列表、当前版本和启用统计使用有界 JOIN/聚合查询；列表读取固定为四次 SELECT，
与文档数量无关（`O(1)`），不会在文档循环内查询数据库。Worker 的四次 Agent 检索只做
内存匹配，不产生 N+1 数据库请求。

## 8. 迁移与回滚

迁移 `20260827_0017` 创建上述三张表、唯一约束、容量检查和检索所需索引。降级会删除
知识库全部表及内容，属于破坏性操作，只能在明确备份后执行；普通发布流程只允许向前
执行迁移，不通过回滚来撤销文档内容。
