# 团队成员与仓库策略

首版服务一个团队的多个 GitHub 仓库，复用现有角色、资源范围、分页、任务和审计。
后台入口为“团队管理”；只有具有 settings:manage 权限的管理员可维护。

## 成员

- 配置管理员继续使用现有部署配置，不能从页面修改或停用。
- 旧额外账号在认证服务首次初始化时一次批量导入 team_members，冲突时不覆盖。
  导入保留角色、密码哈希和原资源范围；旧普通成员首次迁移后需要重新登录。
  后续重启不会恢复被停用的账号，也不会覆盖页面修改的密码或权限。
- 新增、编辑使用 PUT /api/v1/team/members/{username}，携带 expected_revision。
  创建使用 0，更新使用页面取得的当前版本；重复创建和过期版本返回 409。
- 每次认证从用户名规范化唯一键读取当前启用状态、角色、资源范围和 revision。
  签名会话绑定成员版本；修改角色、范围、密码或启停状态时递增版本并撤销旧会话。
  HTTP 后续请求立即失效；已有 SSE 每两秒检查会话并停止后续推送。
- 非管理员不能申请 unrestricted 范围。管理员也可保留有限的任务可见范围；
  全局配置和成员管理仍属于管理员权限，不是一个独立企业的租户隔离。
- 密码仅在事务外执行 Argon2id 哈希计算，响应和审计不包含密码及哈希。

## 仓库策略

GET/POST /api/v1/team/repositories，PUT /api/v1/team/repositories/{id}。
仓库名采用 GitHub 的 owner/repository，忽略大小写确定身份；创建后不重命名。
仓库仍必须处于既有 GitHub App 和服务端入口白名单授权范围，策略不会扩大外部访问权限。

| 字段 | 含义 |
| --- | --- |
| enabled | 是否接收新的手工任务、Webhook 任务和重新审查 |
| target_branches | PR 目标分支，支持 main、release/* 等匹配；空列表表示全部 |
| knowledge_sources | null 继承知识库；空列表不使用知识库；其他值选择已启用文档来源 |
| max_model_requests | 可选的单次审查请求上限，包含所有 Agent、重试和格式修复 |
| approver | 指定审批用户名；空值按原角色审批，全量范围管理员可代办 |

创建运行的事务通过 repository_key 唯一索引读取一次策略，并把完整策略与 revision
保存到 review_runs.repository_policy。旧运行继续使用自己的快照；重新审查使用新策略。
未配置策略的仓库继续原有行为，不修改已有历史任务。

暂停仓库后，手工提交和重新审查返回 409；Webhook 返回 accepted=false、
reason=repository_paused。幂等重放仍返回已经接收的原任务。
Worker 取得当前 SHA 的 GitHub 上下文后检查目标分支；不匹配时取消任务并记录
review.policy_skipped，不产生审查成功结论，也不调用审查模型。

知识规则选择只控制 Markdown 知识库，仓库自身的 AGENTS.md 和代码检索继续生效。
知识内容沿用现有知识库版本机制，策略快照固定的是来源范围，不冻结这些文档未来的内容。
审批负责人在保存时检查账号、审批权限和仓库范围，最终动作继续经过服务端资源权限检查；
负责人后续停用时，全量范围管理员仍可代办。

请求上限在每次审查模型 HTTP 调用前，以一条带当前租约条件的 UPDATE 原子预占，
并在请求发出前提交事务。失败和未完成的预占也占用额度；重新领取或重试不会清零。
达到上限后停止新调用，任务明确失败，已完成批次保留；可调整仓库策略后重新审查。
它不包含向量、精排请求，也不是费用结算。未设置上限时沿用原执行方式，不新增逐请求计数。

## 查询规模与审计

预期首版为数十至数百成员、数十至数百仓库；任务仍按万行至十万行处理。

- 成员、仓库、审计列表复用 CursorPage 和 created_at/id 稳定游标，每页默认 10、最多 100。
  每页一条 SQL，查询次数 O(1)；成员列表不读取密码哈希。
- 认证使用 team_members.username_key 唯一索引；旧会话撤销使用 admin_sessions.username 索引。
- 仓库查找使用 repository_policies.repository_key 唯一索引；选定知识文档通过 source IN
  一次批量校验，不逐条查询。
- 额度预占按 review_runs 与 review_tasks 主键限制；每个真实请求预占一次，整体 O(Q)。
  Q 是需要分别授权的模型请求数，包含动态重试，不能预先批量扣除尚未确定的请求。
- 成员和仓库变更与 Outbox 审计在同一事务提交。GET /api/v1/team/audits 提供分页，
  使用 (aggregate_type, occurred_at, id) 索引，记录操作人、对象、版本与非敏感配置。

## 验证与后续

回归用例覆盖成员越权、旧会话失效、旧账号导入、版本冲突、策略快照、分支过滤、
审批负责人、额度并发和模型格式修复请求拦截。测试在现有 CI 的隔离环境执行，
部署后再通过 Chrome DevTools 检查管理页面。

月度费用管理、通知待办和真实模型质量评测属于后续迭代。真实 PR 评测应复用
evaluation.md 的样本和双人裁决规范，未测量前不填写准确率或效率提升数据。
