# OpenReviewer 八项整改与本地验收

本轮基于 `main`、`79d19f497199b9d26b597034dfce44307ac349f6` 修改；未提交、推送或部署，未修改线上配置、授权、文档或审查数据，喵。

## 改动与使用

| 项目 | 实现及操作 | 验证重点 |
| --- | --- | --- |
| 1. 移除补充规则 | 删除网页入口、前端调用、后台 `project-pack` 路由及服务方法。保留新建、编辑和 Markdown 导入。 | 入口不存在；新的内置文件不会自动补入已初始化的库。 |
| 2. 真正删除 | 文档可进入回收站、恢复，或确认后彻底删除正文及所有文档版本。仅保留文件名、删除人和时间，阻止内置资料重新导入。 | 清空后重启不重新初始化；维护同步跳过删除记录；固定方案的新审查也过滤已删除或停用的资料。旧报告中的引用和证据快照保留。 |
| 3. 历史版本重试 | “复查此版本”固定已保存代码并独立成报告；“检查最新提交”在服务端回查 GitHub。旧版本失败节点重试先转为历史运行，复用已成功批次。模型完成后出现新 SHA 时保存为历史报告。 | 版本校验限定安装、仓库、PR；历史报告不发布、不改当前问题生命周期；批次页可展开查看过程候选。 |
| 4. 自动准备向量 | 开启关联代码且允许外部调用时，自动排队准备当前 SHA 的基础索引和预算内缺失向量，审查等待必要准备后继续。相同内容向量复用。 | 数量和请求上限、失败、暂停、准备超时有覆盖说明；已有检索证据继续使用原快照。每轮向量准备限时 3 分钟（另受单请求超时约束），审查等待最多 10 分钟。 |
| 5. 搜索记录及检索对比 | 普通搜索自动保存到“搜索记录”，按所选仓库、提交、查询原文和请求策略分页回看实际策略、耗时与代码。“检索方式对比”填写应该找到的符号后即可在网页执行。 | 搜索刷新后仍在；不再按临时缓存清理；普通搜索不会生成评测报告。对比保存查询、提交、人工参考符号和实际返回；降级不生成误导性对比。 |
| 6. 单人效果评测 | 选择一份结果 → 保存有效、误报或暂不确定判断 → 完成核对并查看统计。第二份同提交结果的比较收在可选入口。 | 单账号可完成；未核对和不确定单列；未知费用保留未知；没有参考缺陷时不计算召回率。核对来源如实标为单人，以最近保存的判断为准。 |
| 7. 统一成员 | 初始管理员首次启动导入成员表，之后和普通成员共用认证与权限版本。列表标明初始管理员；可在网页改密码，角色、启用及全部权限保留以保障管理入口。 | 不重复导入、不覆盖新密码；改密码吊销旧会话；历史操作人记录不改写。 |
| 8. 仓库接入 | “项目与成员 → 接入仓库”读取现有 App 的授权账号和仓库；缺少仓库时为同一 App 补授权，返回刷新后检查并启用。 | 校验 App 归属、读取代码/PR/CI 权限、PR 事件订阅和仓库访问；通过才保存网页接入许可。重新检查失败时保存原因并撤销该网页许可。只存策略显示尚未检查接入。 |

## 数据与运行约束

新增迁移 `0061` 至 `0063`：删除事实表、索引准备起点、仓库连接元数据及安装编号索引。迁移不删除既有业务数据。就绪探针版本同步为 `20260914_0063`，喵。

首次启动会把部署配置的初始管理员导入成员表；以后数据库中的密码为准，已有账号不会被配置重新覆盖。升级后原管理员会话可能需要重新登录。此方案不修改 GitHub App，也不要求为新仓库重新部署，喵。

| 数据访问 | 规模边界与查询方式 |
| --- | --- |
| `knowledge_documents`、`knowledge_document_versions`、`knowledge_deletions`、`knowledge_library` | 沿用最多 128 份文档、5 MiB 内容边界；主键、source 唯一索引和文档版本索引。删除、活动文档过滤、维护补充均为 O(1) 次查询或批量操作。维护多了一次删除事实查询，2 份与 32 份文档的查询次数相同。 |
| `review_runs`、`review_tasks`、`review_plans`、`model_review_batches`、`review_findings`、`finding_lifecycles` | 运行主键和计划/角色/批次索引；重试最多检查 3000 个批次并批量更新，结果保存不按问题逐条查库。批次和候选按页读取。 |
| `code_indexes`、`code_index_chunks`、`code_chunks`、`code_embeddings`、`retrieval_traces` | 沿用最多 1000 个文件、20000 个代码块；缺失向量按 200 块分页、供应商接口每批最多 20 块；缓存和请求治理复用现有封装。历史按索引及创建时间分页，查询和策略在该提交内过滤。 |
| `evaluation_datasets`、`evaluation_cases`、`evaluation_observations` | 每份评测最多 200 个 PR、每份结果最多 500 条问题；列表分页、统计在数据库聚合。概览固定两次查询，对比固定一次聚合，无逐样本查库。 |
| `team_members`、`repository_policies`、`admin_sessions`、`outbox_events` | 成员用户名唯一键、仓库唯一键及新安装编号索引。每次认证、接入检查、许可判断均为 O(1) 次查询；GitHub 网络检查与密码计算放在数据库事务外。 |
