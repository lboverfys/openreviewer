# 管理页面首屏与分页优化（2026-09-12）

本次针对进入页面时的等待和大列表加载，保留现有 React、FastAPI、PostgreSQL 架构。

## 确认的原因与修改

- 控制台原先优先等待 SSE，普通接口的首次兜底延迟 3.5 秒；现在立即读取首屏，SSE 继续负责实时更新，两者复用前端请求缓存。
- 控制台原先每次读取 50 条并累积“加载更多”的结果；现在每页 10 条，翻页替换列表，首页实时更新不会覆盖正在查看的后续页。
- 页面代码和首屏接口原先先后加载；现在导航悬停、聚焦或点击时并行预取页面代码和一个主要 GET，复用已有的请求合并和有界缓存。加载期间保留导航外壳。
- 检索页原先等待索引、提交、配置、运行状态、评测五组请求全部完成；现在各区域独立显示，评测在打开标签后才读取。重新进入页面可立即使用会话缓存，后台校验不会覆盖配置草稿。
- 知识库的 Markdown 渲染器只在打开“预览”时加载，编辑列表首屏无需下载该组件。
- 审查详情原先通过 CSS 隐藏其他标签，但仍生成问题、批次和最多 500 条上下文事件对应的界面；现在只挂载当前标签，日志和问题使用独立分页接口。详情变化后更新当前列表页，并保留页码。

## 分页范围

| 列表 | 方式 | 默认大小 |
| --- | --- | --- |
| 审查任务 | 服务端 `(created_at, id)` 游标；状态和关键词在服务端过滤 | 10 |
| 审查问题 | 独立接口，沿用已有 Finding 游标；严重度、裁决状态和关键词在服务端过滤 | 10 |
| 运行日志 | 独立接口，按 `(occurred_at, id)` 倒序游标；支持日志类型过滤 | 10 |
| 代码索引、可选审查提交、评测报告 | 服务端 `(created_at, id)` 游标 | 10 |
| 知识文档 | 服务端 LIMIT/OFFSET；复用文档总数上限 128 | 10 |
| 文档版本 | 按版本号倒序游标；历史列表不读取旧版本正文 | 10 |
| 配置变更记录 | 按 revision 倒序游标；展开后加载 | 10 |
| Agent 批次、CI 检查、检索候选证据 | 对已有有界快照分页渲染 | 10 |

任务文本搜索至少输入 3 个字符，以匹配 PostgreSQL trigram 索引；纯数字可直接匹配 PR 编号。改变筛选条件后回到第一页。知识文档搜索覆盖文档路径与当前内容。

详情中的事件快照仍用于已有阶段和 Agent 进度推导，不直接等同于完整日志总量；完整历史通过新的日志分页接口读取。

## 数据访问与规模

- 审查任务按万行以上历史设计。分页涉及 `review_runs`、`review_tasks`、`pull_request_versions`、`review_plans`、`review_findings`；普通翻页只做总数、当前页、当前页指标三条 SQL，不再重复计算各状态和读取 Worker。查询次数为 O(1)，测试比较 1 条和 20 条页面均为 3 次。总数是必要的数据库聚合，不把全量记录读入应用。
- 问题和日志翻页先通过索引核对任务资源范围，再读取当前页；分别访问 `review_findings` 与 `outbox_events`，查询次数为 O(1)。不重新加载详情、CI、模型调用或评测准入数据。
- 检索列表涉及 `code_indexes`、`review_runs`、`retrieval_evaluations`；每种列表单条有界查询，最多取 `limit + 1` 行判断下一页，查询次数为 O(1)。索引列表只读取展示列。
- 知识库最多 128 份文档，访问 `knowledge_documents`、`knowledge_document_versions` 和库状态，复用 JOIN、文档唯一键和版本唯一键；配置记录通过 `configuration_audits.revision` 唯一索引翻页。均无逐条数据库查询。
- 原有前端缓存上限保持 128 项、8 MiB，最长保留 5 分钟；登录、退出和写入沿用原有失效机制。列表不在组件中无限追加。

## 迁移与兼容

新增迁移 `20260912_0051`，增加索引、评测、状态任务与日志的完整排序键索引，以及 PR 编号和任务文本搜索索引。PostgreSQL 需要 `pg_trgm`，迁移会执行 `CREATE EXTENSION IF NOT EXISTS pg_trgm`；SQLite 回归跳过 PostgreSQL 专用 GIN 索引。

`/api/v1/retrieval/targets`、`indexes`、`evaluations` 的返回值由数组变为 `{items, next_cursor}`。新增 `/api/v1/reviews/{id}/findings` 和 `/events`；OpenAPI 快照和前端类型一起更新。部署时应同时更新 API、前端并执行迁移。

## 验证范围

本机 Python 3.12 隔离测试验证分页边界、同时间戳排序、资源隔离、服务端过滤、查询次数和迁移；前端验证首次 GET、当前页替换、实时更新、按标签加载以及刷新保留当前页。

Chrome DevTools 在本机隔离预览中验证了 64 个任务、23 个索引、28 份知识文档、23 个历史版本、23 条配置记录，以及包含 25 个问题和 120 条日志的详情。首屏任务只读取和显示 10 条，详情概览没有挂载问题、批次或日志行，未保存的知识草稿在翻页后保留。

本机 SQLite 和浏览器结果不代表线上 PostgreSQL 响应时间。本次没有登录服务器、部署或调用真实审查、向量、精排模型；上线后的实际改善仍应结合真实接口耗时与 PostgreSQL 执行计划确认。
