# 审查读取与调度优化

管理页继续使用现有 React、FastAPI 和 PostgreSQL。

- 详情 GET 新增 `view=overview/findings/agents`；默认 `full` 保持原有返回行为。概览跳过问题页和评测样本，问题仍走独立分页接口。CI 信息继续用于可见侧栏。
- 概览事件按任务、事件类型和角色取最新状态，最多128条。事件只用于阶段说明，完整日志通过原有分页接口读取。批次数、完成数与Token用量从 `model_review_batches` 聚合，不依赖最近500条日志；批次明细展开后每页10条。
- 任务首页读取最新精确总数；后续页在5秒内复用同权限范围、同筛选条件的总数。缓存最多128个整数项，单进程内共享，不新增外部缓存服务。首页与缓存过期时通常3条SQL，后续页通常2条SQL，查询次数均为O(1)。
- 审查上下文先收集三个角色的最多24组查询，批量预取向量、去重完整检索，并按角色轮流分配精排机会。沿用现有持久化额度、暂停开关、请求缓存和共享单并发通道。精排提供方每次只支持一个查询，因此仍需有界逐组调用；不同语义查询的数据库检索次数为O(Q)，Q最多24，同一查询不再为多个角色重复执行。
- 每领取4次审查任务，Worker 给索引一次机会；没有待建索引时立即继续审查。空闲时沿用原有索引领取方式。

数据库访问涉及 `review_runs`、`review_tasks`、`review_plans`、`review_findings`、`outbox_events` 和 `model_review_batches`。列表按万行至十万行设计；进度按单任务最多3000批次设计，只读取聚合结果和当页字段。复用任务主键、计划运行唯一键、批次 `(review_plan_id, agent, batch_number)` 和事件任务排序索引。没有逐行查询问题或批次。

CI 使用隔离 PostgreSQL 验证一万及十万条任务，按1000行批量造数，测试结束回滚。记录20次翻页的SQL次数、P95耗时和索引执行计划，不访问业务库或真实模型。实际网页通过部署后的 Chrome DevTools 验收；本机不创建环境、数据库或测试服务。
