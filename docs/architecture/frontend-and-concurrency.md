## 页面加载

仪表盘、设置、知识库、检索和审查详情通过 React.lazy 分别加载。登录界面和认证判断保留在入口文件中；只有认证完成、权限允许且路由匹配后才加载目标页面。页面加载期间显示原有等待界面；资源下载或渲染失败时显示明确提示和手动刷新入口，避免自动刷新循环。

同一版本 Node 22.19、同一锁文件、同一构建命令，对构建清单中的入口及其静态依赖求和：

| 范围 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首次加载 JavaScript | 496,565 B | 217,905 B |
| 相同 gzip 参数压缩后 | 148,600 B | 68,276 B |
| 独立页面入口 | 0 | 5 |

首屏 JavaScript 减少56.1%，相同 gzip 参数下减少54.1%。后续页面在首次打开时下载，浏览器继续复用已加载模块。这是构建体积对照，不是浏览器首屏耗时测量。

DOM回归覆盖：未登录不加载业务页面、无权限不加载设置页、页面切换复用模块、审查与检索深链接、加载失败不重复请求。保留现有Hash路由和权限规则。

发布前，服务器独立环境中135项前端测试、覆盖率门槛、TypeScript检查和生产构建通过；Ruff、94个后端文件的Mypy与OpenAPI一致性检查通过。本轮未改动后端生产代码或数据库结构，全量后端回归继续由现有CI执行。

## 并发回放条件

在niuma-2的独立PostgreSQL备份副本上运行，使用948个文件、10,029个代码块和8,327条已有代码向量。正式数据库未用于压测。

- API：1 CPU、512 MiB，单个Uvicorn进程，生产默认数据库连接池5+5。
- PostgreSQL：1 CPU、512 MiB；客户端独立容器：0.5 CPU、192 MiB。
- 真实HTTP回环请求，包含路由、数据库会话验证、每次请求的配置读取及响应序列化；登录在计时前完成。不包含公网、TLS、Nginx和真实模型延迟。
- 所有Embedding与Reranker调用均由内存模拟实现；不读取或解密真实模型Key，真实API暂停环境变量始终为true。模拟配置适配器仅让测试请求进入模拟客户端。
- 16并发首次加载；各策略1、4、8、16并发，每组40次；另有不重复查询和两个16并发的30秒持续回放。
- 混合检索提前预热20条固定查询的模拟向量及精排缓存。该场景用于测本地检索链路，不代表真实模型服务吞吐或准确率。

最终记录1,765次计时请求，另有20次串行预热。全部请求成功、无策略降级，手工检索记录增长为0，各组完成后数据库连接均已归还。16个请求同时首次查询只加载1次词法索引。

| 场景 | 并发 | 请求数 | 中位耗时 | P95 | 吞吐 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 关键词，索引首次加载 | 16 | 16 | 2,870 ms | 2,903 ms | 不作为稳定吞吐 |
| 关键词，热缓存短回放 | 1 | 40 | 36 ms | 49 ms | 26.8次/秒 |

API进程记录的峰值RSS约182 MiB，测试容器限额512 MiB；这不是长期内存稳定性证明。并发增加后吞吐没有线性增长、等待时间明显上升，说明这一限额下继续增加同时处理数量不能直接换来更高吞吐。本轮未调整线程池或生产并发参数，也未证明具体CPU热点；需要更高吞吐时，应按真实请求组合继续分析耗时和资源使用。

首次查询约2.9秒的集中等待仍存在，首次词项构建与串行冷加载属于当前边界。短时回放未覆盖长时间运行、多实例、真实模型未命中、外部限流和公网连接，因此不能将16并发称为生产最大容量。

## 数据访问范围

每个请求访问admin_sessions、code_indexes、retrieval_settings、code_index_chunks、code_chunks；关系策略增加code_relations；混合策略增加code_embeddings与retrieval_rerank_cache。关键词、关键词加关系、缓存命中的混合精排分别为4、5、12条SQL（包含向量查询的事务内参数设置），每个请求都是O(1)次数；没有按候选逐条查询。候选正文最多150块，当前融合上限30块。

首次词法加载使用已有的500行游标批次，上限20,001行；多请求共享同一份加载结果。手工搜索不保存候选正文。回放检查冷加载次数、请求失败、策略降级、临时记录增长和归还后的连接数。

## 复现

脚本为 `tests/performance/retrieval_http.py`，仅在显式授权的独立容器和备份副本中执行。它要求本地隔离数据库名为openreviewer_perf、连接地址为127.0.0.1、OPENREVIEWER_BENCHMARK_DISPOSABLE=true、OPENREVIEWER_RETRIEVAL_API_DISABLED=true；服务仅监听隔离网络的回环地址，不发布宿主机端口。基准控制端点不会注册到生产应用。

1. 用项目锁定依赖准备测试环境，恢复对应数据副本；服务端执行 `python -m tests.performance.retrieval_http serve`。
2. 在共享该隔离网络、独立CPU限额的客户端容器执行 `python -m tests.performance.retrieval_http run --sustained-seconds 30 --output /work/artifacts/concurrency-final.json`。
3. 保存报告后删除本轮测试容器及工作目录，保留正式数据库、模型暂停状态和必要的小型验证报告。
