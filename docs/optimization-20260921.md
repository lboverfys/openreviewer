## 独立真实调用入口

`python -m apps.maintenance.run_review_experiment prepare --repository <仓库> --profile-id <已保存方案>
--run-id <源运行> [--run-id ...] --output <新计划.json>`：只读固定来源，不调用模型。
每批 1–10 个不同 PR/SHA，每个最多 100 文件、2 MiB 输入；总体清单最多 32 MiB。
计划保存源码、规则和已保存的检索上下文，不重新支付向量/精排。方案缺价、跨仓库、来源不全
或当前仓库暂停会拒绝。代码、上下文和方案指纹在执行前重新校验。

`python -m apps.maintenance.run_review_experiment run --manifest <计划.json> --output <全新受控目录>
--budget-usd <已授权金额> --max-requests <1至200>`：会真实调用已保存方案中的模型。
费用按配置价格的请求上界预占，每次重试也占用额度，不释放失败或未知用量的额度。
这限定的是配置估算，不能代替供应商账单。每次 HTTP 身份、请求指纹、可见输出、结算和失败
写入独立实验档案；每条输出 256 KiB、每实验运行 8 MiB。上界额度更保守，可能提前停止。

实验只验证固定输入上的模型审查阶段，复用现有角色筛选、Prompt、供应商协议、分批和汇总。
单并发且关闭结果复用，逐个变体重新请求。它不测试 Worker 排队、租约恢复、GitHub 发布或
冷检索准备时间，不将其耗时称为线上任务端到端耗时。
来源有检索上下文时冻结复用，缺少则保留为空，不编造检索覆盖；冻结准备费用不算入角色差异。
原仓库绑定、源任务和生产日常账本不变。实验有独立费用日志；已配置月度预算的仓库会拒绝
这个独立入口，避免绕过其运营额度。普通 Worker 不暴露排除角色的参数，默认三路行为保持。

归档目录含 `plan.json`、逐次调用输出、请求日志、独立运行结果、`report.json`、空白人工复核包
和逐文件哈希。所有成功、失败和未结算记录保留；报告中的人工质量指标保持 null，直到实际复核。
当前试点明确是 `pilot_not_validation`；不能当成既有 20 组参考配对的正式方案验收。
该目录包含受控源码，不提交 Git；Windows 强制 D 盘绝对路径，不覆盖旧实验。
