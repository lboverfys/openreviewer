# OpenReviewer 使用手册

平台接收 GitHub PR，用固定提交的代码、关联代码与项目规则进行 AI 审查，再由有权限的成员处理结论。它服务一个团队的多个仓库。

网页右上角的“使用手册”可随时打开。日常使用围绕提交 PR、查看结果和处理问题；配置、费用和排错各有独立入口。

## 费用、诊断和错误定位

在“用量与费用”选 UTC 月份，打开仓库请求明细，再在汇总中切换“模型与用途”或“Agent 角色”。
费用占比只在已知费用内计算，未知请求单独列出。P50/P95 是实际 HTTP 请求耗时（含失败），
不是整次 PR 的等待时间；已结算也不表示问题判断正确。

在“运行诊断”选时间范围，完成运行均价包含这些运行跨月发生的请求，缺账本或未完整确认费用
不会被当成零。引用核验分开显示覆盖率与可核验样本通过率，来源异常、未覆盖、未知原因另列。
批次“重复领取”不等于 HTTP 重试次数。索引复用、Agent 整组缓存全命中、审查结果复用分别读，
估算避免的输入 Token 不代表实际账单扣减。

遇到接口错误，可以在通知中点击“复制请求 ID”，连同当前任务 ID 提供给管理员。
管理员按 [部署排障说明](../deployment/README.md#请求与运行关联排障) 查对应事件；不要把模型
正文、凭据或完整源码贴进普通日志。未接通外部告警时仍需查看诊断和现有监控页面。

## 每个入口负责什么

| 入口 | 什么时候使用 | 会发生什么 |
| --- | --- | --- |
| 审查任务 | 看新 PR、失败原因和当前进度 | 每次审查单独记录，打开后先看状态与结果；尝试次数不再冒充完成进度 |
| 问题处理 | 需要核对结果、跟进修复或审批时 | 从具体问题建立跟进项，记录负责人和处理状态 |
| 模型与审查设置 | 接模型、填价格、调整关联代码时 | 配置模型、检查分工、处理上限和检索开关；固定配置版本收在高级入口 |
| 规则文档 | 业务规则、项目约定变化时 | 阅读和编辑文档，一键开启或暂停使用；可移出列表和恢复 |
| 规则文档 → 搜索代码 | 核对 AI 看过的关联实现时 | 查询固定提交的代码索引；任务通常自动准备索引 |
| 项目与成员 | 接入项目、调整权限或审查范围时 | 项目设置和成员权限分别管理，预算等选项按需展开 |
| 效果评测 | 核对准确性或比较两组结果时 | 选择原结果、新结果并逐条复核；默认用于正式验收，不自动再跑模型 |
| 用量与费用 | 核对请求和支出时 | 查看费用估算、预算与待确认用量 |
| 运行状态 | 任务不动或服务报错时 | 查看后台节点、模型通道和错误记录 |

## 一次普通审查

1. 管理员在“模型与审查设置 → AI 模型”保存连接、模型名称和估算单价。连接测试会真实调用服务商；通过后启用。
2. 三路 Agent 分别检查安全、规范和逻辑。相同模型可继承公共连接和价格；需要独立模型时再覆盖。
3. 知识文档选择正确仓库，正文写清适用场景、约束和缺陷证据，不依赖外部链接；来源核对另存维护记录。启用后才供新任务选择，已有任务和固定方案保留原快照。
4. 提交 GitHub PR，平台自动接收。CI 就绪后准备代码索引和上下文，再发起模型请求。
5. 在任务详情查看本次实际模型、请求 ID、Token、耗时、知识引用和检索来源。历史结果展示其原模型，不随当前配置改名。
6. 核对候选问题，再决定批准、发布、驳回或重试；批准不会自动发布到 GitHub。

三路结果无需进一步模型去重时，程序完成汇总，页面显示“已完成程序汇总”。此时第四个模型没有请求、不产生第四路 Token，用实际适用节点计算完成进度。

## 暂停、取消和重新测试

- 暂停后保留任务，可以继续；取消结束本次任务，后续步骤停止执行。已发出的模型请求可能仍有费用。
- 已取消、已关闭或已合并的 PR，可以在完整代码快照存在时使用“复查此版本”。它另建一条真实模型审查记录，使用当前设置，禁用本次的历史结果复用。
- 历史复查不重跑 CI、不进入批准和 GitHub 发布步骤，不改写原任务或当前 PR 的缺陷生命周期。结果仍可在平台查看或用于效果评测。
- 管理员可在“审查方案”基于旧版本创建 Prompt 候选。先记录对照假设并查看差异，再回到
  一份代码完整的审查详情，在“本次试跑方案”选择基线或候选，分别执行“复查此版本”。
  两次都使用同一源运行，按需要勾选输出留存；仓库当前方案不会因此切换。真实效果仍需人工复核。
- 普通“检查最新提交”重新走 GitHub 流程；如果 PR 已关闭或仍是草稿，平台会停止普通审查。
- “重试失败部分”保留已成功的批次。需要重新执行整个阶段时再展开“高级重试”，页面会说明哪些结果将重新计算。

## 文档移出后怎么恢复

1. 打开“规则文档”，切到一直可见的“已移出文档”。
2. 选择目标文档，点“恢复并使用”，恢复与启用在同一次操作中完成。
3. 刚误移出时也可以直接点提示条中的“撤销移出”，恢复原来的使用状态。

“暂停使用”仍把文档留在列表，点击后直接保存；编辑正文和仓库范围则要点击“保存修改”。旧正文在“历史版本”中，移出不会删除历史。

## 两个检索开关

- “审查时自动补充关联代码”决定审查是否自动检索同一提交的上下文。
- “允许向量与精排模型调用”决定是否调用百炼向量/精排服务。关闭后仍可用关键词和代码关系检索，不会暂停 GPT 审查。

开关位于“模型与审查设置 → 关联代码”，保存后对下一次检索操作生效。首次未保存时兼容原部署默认值；页面保存后的值优先。它是运营开关，不冻结在历史方案中。已发出的 HTTP 不会因随后关闭开关而凭空撤销。

索引有新增向量数与请求次数上限。达到上限时保留基础索引并显示原因；需要时在限额内继续补齐，不会一次性无界生成全部向量。

## 知识资料来源

内置知识为 5 份通用审查规则和 5 份限定 NiuMa 的业务规则，已经对照本地代码、迁移、测试和飞书资料提炼。正文不包含操作教程、接口清单、环境日志和来源链接；每个章节可独立用于判断问题。来源、冲突取舍和维护方法见 [审查知识整理与来源核对](knowledge-curation.md)，该维护文件不进入模型检索。

“补充项目资料”只添加缺少的项目文档，保留已有人工编辑、停用和归档状态，不会覆盖已有正文。批量替换本轮旧知识使用维护命令先预览，再按版本显式更新；旧文档保留历史，合并掉的文档归档。它不自动同步飞书，规则变化仍需核对当前实现与明确业务决定。

已排除旧多角色说明、占位响应和“业务模型仍未定”的旧现状。点单请求的订单创建与积分支付按当前原子事务核对；环境中某项能力暂未配置，只约束其失败行为，不写成永久禁止接入的规则。

## 价格和统计口径

OpenAI 参考价来源：https://developers.openai.com/api/docs/pricing ，核对日期 2026-09-13。`gpt-5.6-luna` 标准短上下文每百万 Token：输入 $0.20、输出 $1.20、缓存读取 $0.02、缓存写入 $0.25。

百炼参考价来源：https://help.aliyun.com/zh/model-studio/model-pricing ，北京地域 `qwen3.7-text-embedding`、`qwen3.7-text-rerank` 均为人民币 0.50 元/百万输入 Token。美元参考折算使用 Frankfurter 2026-09-11 的 USD/CNY=6.7082，向上取到六位小数为 $0.074536。汇率来源：https://api.frankfurter.dev/v1/2026-09-11?base=USD&symbols=CNY 。

这些是可修改的估算参考，不是中转站实际账单。长上下文、加速、地区和优惠可能改变价格。没有记录用量或历史报价时显示未知，不按当前价格改写旧费用。

## 如何开始评测

1. 打开“效果评测”，选择一份已完成的审查结果。
2. 给问题选择“有效问题”“误报”或“暂不确定”，保存结论。
3. 点击“完成核对并查看统计”。一个账号就能完成；没有核对的问题也会单列。

“评测结果”显示有效、误报、未核对、不确定数量、模型耗时和已知费用。没有可靠漏报参考时不计算召回率；未知费用不当成零。单人核对如实标明来源，不声称双人独立审核。

创建时可选择“双人独立验收”，创建后不能切换。两位不同成员分别核对全部问题并提交，
首次提交前看不到对方判断；第三人不能加入同一项复核。修改已提交判断后需重新提交。
处置分歧、参考匹配分歧和定位分歧分开显示。严格报告排除来源不完整或跨提交复用结果，
单人记录仍可日常使用，但不能让候选方案获得“双人验收”资格。

需要比较模型或配置时，再添加同一 PR、同一提交的第二份审查。提交、模型、Prompt、知识和检索版本可在“模型与版本”查看。可靠的参考缺陷是可选项，仅在计算找回率时需要。

## 接入另一个仓库

1. 在“项目与成员”点击“接入仓库”。
2. 选择现有 GitHub App 已授权的账号和仓库。已授权所有仓库时直接选择即可。
3. 目标仓库不在列表时，打开“到 GitHub 补充仓库授权”，给同一个 App 增加仓库权限，再返回刷新。
4. 点击“检查并启用审查”。验证代码、PR、CI 权限和 PR 事件订阅后保存平台许可；新 PR 将自动触发审查。

只保存策略会显示“尚未检查接入”。已连接仓库可随时“检查接入”；访问失败会保存原因，并撤销这条网页接入许可。原有部署允许名单兼容保留，增加新仓库不需要修改服务器配置。

## 删除规则和回看搜索

规则可移到回收站后恢复，也可以确认后彻底删除。彻底删除会删除正文和文档版本，仅保留防止自动导入的删除事实。旧审查已保存的引用和证据不变；新任务，包括使用固定方案的任务，不再使用这份规则。

手动代码搜索会自动保存到“搜索记录”，按仓库、提交、查询和策略回看。在“检索方式对比”填写“应该找到的完整代码符号名”后，才会生成带标注依据的效果报告；普通搜索不自动算成评测。

自动审查先建立本次 SHA 的基础索引，再在开关允许时复用向量并补齐预算内的缺失部分，然后检索、排序并送交三路 AI。达到数量或请求上限、失败或超时会记录实际覆盖和基础检索回退原因。向量缺失不等于变更代码没有送给 GPT。

历史任务使用“复查此版本”固定已保存代码；“检查最新提交”会重新读取 GitHub 的最新 SHA。历史复查独立保存，不能发布为当前 PR 的结果，也不会改变当前 PR 的问题状态。
